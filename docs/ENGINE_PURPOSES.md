# Engine purpose mapping

V7 uses baseline, adversarial and scenario/correlation tests; V2 uses empirical, generative and adverse models. These naming schemes are not automatically equivalent. Store each run's actual purpose, assumptions, seed, input/code hashes, trials and hit count. The gate checker expects purpose-mapped baseline/adversarial/scenario entries and independently substantiated evidence flags.

Keep adverse stress separate from base probability unless scenario weights are empirically supported. This does not remove scenario/correlation testing or separate joint portfolio simulation. Probability-posterior draws are not simulations of future game outcomes. Do not retrofit acceptance criteria or model coefficients to create qualifiers.

Local ledger hashes are tamper-evident only when the last trusted hash is retained outside the ledger. Cooperative Linux file locks do not provide a distributed or authenticated production audit store.
